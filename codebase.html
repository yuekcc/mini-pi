Files
main.c3 · rat_loop.c3 · api/api.c3 · api/api_worker.c3 · util/cmd.c3 · util/ctrl_c.c3 · app/event.c3
Problem
Two delivery mechanisms overlap — an atomic flag consumed immediately plus queued CANCEL_REQUEST/CANCEL_TOOL events read only at IDLE, making the event distinction semantically dead; the L1/L2/L3 decision lives in the UI loop while its consequences live in three states; shutdown leaks one ApiResponse per in-flight request.
Solution
One deep Interrupt module owning level decision, flag + child-kill, and turn unwinding; the queued-event mechanism is deleted. Consequences move into the Session module from card 1.
Wins
  • One delivery mechanism to reason about
  • Shutdown leak fixed at the seam
  • Cancel path testable without real Ctrl+C
  • CANCEL_TOOL vs CANCEL_REQUEST dead weight gone

Problem
AppContext is a service-locator bag — most methods are one-line pass-throughs — yet every test pays 8 init args for it; the state machine takes only AppContext*, so AWAITING_API is exercisable only through a real curl round-trip and CANCELLING/L2 only through real Ctrl+C.
Solution

Wins
  • AWAITING_API / CANCELLING reachable in tests
  • The interface is the test surface
  • AppContext stops being the one thing every test pays for

Top recommendation

Card 1 — the Session module. rat_loop.c3 is the codebase's hot spot — 665 lines, touched by nearly every commit in the v2 history — and the session-end policy plus discard semantics are where two provable defects live (the off-by-one discard, the hidden start_new_session ordering). It is also the prerequisite for card 2: once Session owns turn unwinding, the interrupt path's consequence-side collapses into it.

Field notes — small defects found en route

All three fixed in d78ed2a.

Second-resolution task IDs collide · fixed

timestamp_id now appends a process-local monotonic sequence + pid, so Bash/Task output files, tool-call ids, turn/request ids and session ids are unique even within one second; lexicographic ordering of turn_ids is preserved.

MP_PARENT_SESSION leaks on nested Task · fixed

Restore is now decoupled from set: the old value is captured first, set/clear happens per id-availability, and the environment is unconditionally restored after the child exits — a grandchild can no longer inherit a stale outer link.

request_id lifetime fixed by parameter passing · fixed

The borrowed request_id alias field was removed from AppContext; execute_one_tool builds the ToolContext from its own request_id parameter instead of reading shared state.
